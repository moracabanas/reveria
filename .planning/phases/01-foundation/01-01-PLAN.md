2. Create ReversoModel class:
   - __init__(self, model_size: str = "small", device: Optional[str] = None)
   - If device is None: use "cuda" if torch.cuda.is_available() else "cpu"
   - Log GPU availability and selected device
   - Load model using Moirai/uni2ts pattern (use SalesforceAIResearch/Moirai as reference since Reverso returns 404)
   - Store model reference

3. Create load_model() async function:
   - Called during FastAPI startup via lifespan
   - Attempt to load model on GPU if available
   - If CUDA unavailable or fails, fall back to CPU with warning log
   - Return ReversoModel instance

4. Create graceful error handling:
   - If model loading fails completely, raise RuntimeError with clear message
   - Include "CUDA unavailable - running on CPU" in error message

5. Update `backend/app/main.py`:
   - Import model_loader
   - Add model instance as app state
   - Update /health endpoint to include model_loaded status
   - Use lifespan to load model at startup and cleanup at shutdown
