**Gathered:** 2026-04-28

<domain>
## Phase Boundary

This phase adds test infrastructure to the Phase 3 Frontend. It does NOT modify frontend functionality — all 11 features are implemented and verified manually. This phase adds automated testing so the frontend can be validated programmatically.

**What this phase delivers:**
- Test framework installation (vitest, @testing-library/react, @playwright/test)
- Unit tests for all frontend components
- E2E tests for the full upload → predict → export flow
- Reference dataset (sample CSVs for controlled testing)
- CI/CD pipeline with test gates

**What this phase does NOT deliver:**
- New frontend features (Phase 3 is complete)
- Backend test infrastructure (Phase 2 has its own test gaps)
- Observability/tracing integration (deferred)

</domain>

<decisions>
## Implementation Decisions

### Phase 3.2 Scope — TEST INFRASTRUCTURE ONLY
- All work is in `frontend/` directory
- No modifications to production code unless required for testability
- All tests must pass in CI before merge

### Technology Choices (Locked)
- **Unit test runner:** vitest (modern, fast, React-friendly)
- **Component testing:** @testing-library/react with @testing-library/jest-dom
- **E2E testing:** @playwright/test
- **CI:** GitHub Actions (`.github/workflows/frontend-eval.yml`)

### Reference Dataset (Locked)
- `frontend/tests/fixtures/sample.csv` — small signal (~20 points)
- `frontend/tests/fixtures/large_50k.csv` — large signal for performance testing
- `frontend/tests/fixtures/multi_column.csv` — edge case with multiple columns

### Test Coverage Requirements
- UploadComponent: file validation, .csv filter, API call mocking
- Chart: D3 rendering with mocked data, zoom handler, view toggles
- MetricsPanel: computation time display, MAE/MSE calculation
- ExportButtons: CSV format validation, PNG/SVG generation
- Full E2E: upload → predict → export flow

### OpenCode's Discretion
- Exact test file structure and naming
- Specific assertion patterns
- CI configuration details (node version, cache strategy)
- Code coverage thresholds

</decisions>
